# 16 合法使用声明、免责与二次开发规则

> 本文是项目的**法律边界文件**。与 [`14-compliance.md`](14-compliance.md) 一起构成本项目的使用条件；任何使用者、分发者或二次开发者都必须完整保留这两份文件。本文不是法律意见，也不构成对任何用途的授权。

## 1. 定位与授权前提

anonchains 是一个**本地代理编排与网络隐私研究工具**：采集公开免费代理列表、验证节点、组织多跳链路并提供本地入口。它不提供攻击能力、不绕过身份验证、不提供任何规避授权的机制。

**本系统仅允许在已获得明确、有效、书面授权的前提下用于红队 / 渗透测试等安全评估。** 授权至少应明确：

- 委托方身份与授权签署人；
- 测试目标资产清单与明确排除的资产；
- 测试时间窗口、速率上限与停止条件；
- 数据处理、报告与销毁要求；
- 双方应急联系人与争议解决方式。

没有书面授权、超出授权范围、或针对第三方系统的任何测试与探测，均不属于允许范围。使用者应自行确认其在所在司法辖区的法律义务；设备所有者、网络运营者与目标系统所有者的许可缺一不可。

## 2. 允许的使用场景（示例，非穷尽）

| 场景 | 必要条件 |
| --- | --- |
| 企业 / 客户委托的红队演练、授权渗透测试 | 有效书面授权 + 明确范围 + 团队内部合规流程 |
| 自有资产或自建靶场的安全评估 | 资产归使用者所有或已获所有者许可 |
| CTF、教学、科研实验 | 隔离环境、不触碰第三方系统、遵守赛事/机构规则 |
| 本地功能学习与协议适配研究 | 只使用公开源与本地回环入口，不对外发起测试流量 |
| 合规的二次开发 / 集成 | 遵守本文第 5 节与 MIT 许可证 |

**仅采集公开、免费、无需认证的代理列表**，遵守 robots.txt、目标站服务条款与速率限制（默认 `crawler.rate_limit_per_second`、`respect_robots = true`）。不得抓取私有或需授权的列表，不得以更换标识、提高重试等方式规避源站限制。

## 3. 明确禁止

- 未经授权对任何系统、网络、设备进行扫描、探测、访问或测试；
- 攻击、拒绝服务、入侵、持久化控制、凭证窃取、钓鱼或恶意代码投递；
- 绕过付费墙、身份验证、访问控制、区域限制或反滥用机制；
- 冒充机构、伪造文件、生成虚假信息或侵犯他人隐私；
- 借助本工具隐藏违法行为来源，或将免费公共代理用于传输真实凭据、机密或敏感个人信息；
- 删除、弱化或绕过本项目的合规边界、限速、回环绑定与安全降级逻辑；
- 任何违反适用法律的用途。

「测试」「学术研究」「假设场景」不能作为上述禁止事项的例外。

## 4. 风险提示与免责

1. **按「现状」提供**：本软件按 MIT 许可证原文所述「AS IS」提供，不附带任何明示或默示担保，包括但不限于适销性、特定用途适用性、不侵权、可用性、准确性与持续性。
2. **不保证匿名**：多跳链、隐匿等级与本地入口**不等于绝对匿名**。节点运营者、时序关联、DNS / WebRTC 泄漏、浏览器指纹、ISP 与国家级观察者仍可能关联身份。本项目不作任何匿名性承诺。
3. **第三方节点不可信**：公开免费代理可能记录、篡改或注入流量，可能随时下线或本身是观测节点。使用者不得依赖其处理敏感数据。
4. **数据风险自负**：池数据、Vault、主口令与备份由使用者自行保管；凭证丢失、密文无法解密、数据损坏或泄露的后果由使用者承担。
5. **合规责任自负**：判断某项活动是否合法、是否获得充分授权、是否需要额外审批，完全是使用者的责任。作者与贡献者不提供法律意见，也不对使用者的判断负责。
6. **责任限制**：在适用法律允许的最大范围内，作者、贡献者与项目维护者对任何直接、间接、附带、特殊、惩罚性或后果性损失（包括数据丢失、业务中断、商誉损失、第三方索赔、监管处罚）不承担责任，无论是否被告知此类损失的可能性。
7. **第三方组件**：sing-box / Xray-core 等外部核心、可选依赖与公开源由各自维护者提供，其许可、行为与可用性不在本项目担保范围内。
8. **无背书**：项目名称、文档或仓库展示不构成对任何组织、产品或测试活动的背书或授权。

## 5. 二次开发规则

本项目采用 **MIT 许可证**（见仓库根目录 `LICENSE`），允许使用、复制、修改、合并、发布、分发、再授权与销售，但**必须遵守以下附加的使用条件与工程约束**：

1. **保留声明**：所有副本或衍生版本必须包含 MIT 许可证原文、版权声明、本文件与 `docs/14-compliance.md`（可翻译，但不得删减实质内容）。
2. **显著标注**：衍生项目须在 README 中明确标注「基于 anonchains 的衍生版本，非官方项目」，并链接回上游仓库；不得以原项目名义发布，避免误导。
3. **不得移除边界**：不得删除或弱化授权前提、禁止事项、免责条款、合规提示、robots / 限速逻辑、`gateway.host` 回环校验、Vault 未解锁时的「敏感字段不落明文」不变量。
4. **不得新增攻击能力**：不得借此代码库实现攻击、未授权扫描、凭证窃取、绕过认证 / 付费 / 访问控制、隐蔽持久化或规避监管的功能。新增协议或解析器须保持「只处理公开列表」的边界。
5. **不得虚假宣传**：不得宣称「绝对匿名」「覆盖全网」「已验证所有节点可用」，不得把「本地探测跳过」包装成「节点可用」。
6. **隐私与遥测**：不得静默回传用户数据、池数据、Vault 内容或出口信息；如新增统计能力，必须默认关闭、明确告知并本地保存。
7. **安全修复**：建议将通用安全修复（脱敏、鉴权、路径处理、加密格式兼容）回馈上游；若发现上游安全缺陷，请通过仓库 Issue 负责任地披露，不要公开可利用细节。
8. **许可证兼容**：分发时须同时满足 MIT 与所引入第三方依赖的许可要求；不得用更严格的条款覆盖上游授予的权利。
