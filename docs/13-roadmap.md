# 13 后续迭代路线图

本文件面向后续开发者或其它 AI：**先读 `docs/README.md` 的迭代约定，再按本文优先级推进**。所有条目都必须保持离线可测、跨平台、合规边界，以及「高匿不等于绝对匿名」的诚实表述。

## 1. 当前版本（0.1.0）已交付

- 任意跳数链路（无硬上限）+ 四种组链 / 轮换模式 + 热更新配置；
- 29 个内置公开源 + 自定义源覆盖 + 可选仓库检索发现 + 5 类解析器；
- 1–4 级隐匿策略、限速 / 抖动 / ETag / robots / 前置代理反哺；
- 候选池 / 可用池双 SQLite 池 + 并发校验 + TTL 增量复检 + 升降级淘汰；
- 内置 Python N 跳级联 + 本地混合入口 + sing-box / xray 配置适配；
- 回环 REST 网关（token 鉴权、写白名单、后台任务）+ 配置总开关；
- Vault 信封加密 + 脱敏日志 + 数字式多级 CLI + 非交互命令；
- 抓取 / 校验界面的实时进度条与百分比、统一相对路径输出、抓取流量优化（响应上限、请求合并、压缩协商、连接复用）；
- 授权红队使用边界、免责与二次开发规则（`docs/16`）及 MIT `LICENSE`；
- 76 个离线单元测试与 `docs/` 全套文档。

## 2. 已知限制（按影响排序）

| 限制 | 影响 | 可能的迭代方向 |
| --- | --- | --- |
| 外部协议只做配置适配，不做本地连通性校验 | 可用池可能含实际不可用的 vless/vmess 节点 | 通过外部核心做真实探测并回写评分 |
| 内置级联仅 TCP 隧道；HTTPS 跳必须最后一跳 | 混合链顺序受限 | 支持多段 TLS 终止 / 本地 TLS 代理（需谨慎设计） |
| 采集前置只支持 HTTP/HTTPS 代理 | SOCKS 可用节点不能反哺采集 | 用内置级联包装 aiohttp 的 connector |
| DNS 泄漏防护仅为运营提示 | 严格场景仍有泄漏风险 | 可配置的带 `detour` DoH 解析器 + 出口一致性断言 |
| `sealed` 为 NULL 的节点在锁定后凭证永久丢失 | 冷启动未解锁时抓取的特殊协议节点不可用 | 抓取前强制检查 Vault 状态；或内存队列暂存并提示解锁 |
| 单进程 SQLite 连接 | 多实例共享池会锁竞争 | 明确多实例隔离约定，或引入轻量服务化池 |
| 免费节点质量不可控 | 通过率低、链不稳定 | 更丰富的健康度指标与历史信誉模型（不采集敏感数据） |
| 无 IPv6 端点 / UDP 协议支持 | 覆盖不全 | 扩展 `utils/net.py` 与解析器，补齐核心映射 |

## 3. 优先级建议

### P1 — 可靠性与可观测性

1. **外部核心探测闭环**：`CoreManager` 生成单节点配置 → 真实请求 echo → 回写 `ValidationResult`，让外部协议节点也有可信评分。
2. **CycleReport 持久化与趋势**：把最近 N 轮报告写入独立 SQLite 表（不含凭证），提供 `/api/reports` 与 CLI 趋势视图。
3. **失败分类**：把 `reason` 结构化为 `timeout` / `auth_failed` / `blocked` / `protocol_unsupported`，便于定位源或节点问题。
4. **日志与指标**：结构化日志（JSON 可选）+ 计数器（抓取字节数、校验通过率、链重建次数），保持脱敏。

### P2 — 能力扩展

5. **更多解析器**：CSV /表格、Clash.Meta 扩展字段、sing-box 原生 JSON 配置导入。
6. **更多协议**：按 [06](06-protocol-adapters.md) 的 6 步清单扩展；任何不可表达协议必须显式 warning，不得伪造 `direct`。
7. **源健康度**：按源统计成功率 / 节点存活率，自动降权或临时停用持续失败的源（不自动启用新源）。
8. **链策略**：地理位置多样性、ASN 去重、跨协议组合约束，避免多跳全部落在同一运营者。
9. **REST 增强**：分页、SSE / WebSocket 事件流（复用 `Scheduler.on_event`）、只读模式。

### P3 — 工程化

10. 打包发布（wheel / Homebrew / Scoop 配方）与 CI 矩阵（Windows / Linux / macOS × Python 3.10–3.14）。
11. 可选容器镜像；注意容器默认不应把网关暴露到 `0.0.0.0`。
12. 类型检查（basedpyright / mypy）逐步清理 warning，保持 0 error。
13. 国际化：菜单文案抽离，保持数字映射不变。

## 4. 明确不做（避免方向漂移）

- 不实现攻击、扫描、未授权访问、凭证窃取或绕过付费 / 身份验证能力。
- 不宣称「绝对匿名」或「覆盖全网所有源」；持续在文档中保持诚实的边界说明。
- 不设计需要公共免费代理运行解密端的链内自定义加密。
- 不把 `gateway.host` 放宽到非回环地址，不提供无鉴权的远程管理。
- 不在未解锁 Vault 时把凭证写明文，不为「方便」绕过该不变量。
- 不引入与需求无关的重型框架，不破坏四层单向依赖。

## 5. 接手一个任务的标准流程

1. 读 `docs/README.md` → 相关专题文档 → 对应源码与测试；
2. 确认改动是否触及 `ProxyNode`、配置 schema、菜单图、REST 白名单或安全不变量；
3. 先写 / 改**离线测试**，再改实现；
4. 更新 `config/anonchains.conf` 注释、对应 docs 文档与本文（若改变了约束）；
5. 跑 `python -m pytest tests -q`、最小离线验证命令、IDE 静态诊断；
6. 手工联网验收仅在需要时进行，并注明外部节点质量造成的波动；
7. 不擅自执行 git 初始化、提交或推送（除非用户明确要求）。

## 6. 版本与兼容性约定

- 配置新增字段必须给默认值，保证旧配置文件可加载。
- `ProxyNode` / `Chain` / `CycleReport` 的 `to_dict()`/`as_dict()` 视为对外契约，新增字段可加、已有字段不随意改名。
- 密文格式（`ANONC1` / `ANONVLT1`）带版本号；任何不兼容变更必须升版本并提供迁移路径，绝不静默把旧 Vault 当作无效文件删除。
- REST 路由只增不删；破坏性变更需新的 `/api/v2/` 前缀。
