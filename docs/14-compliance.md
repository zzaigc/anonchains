# 14 合规使用声明

## 1. 允许的使用场景

anonchains 面向**合法授权**的网络隐私研究、工程测试与本地代理编排：

- 采集**公开、免费、无需认证**的代理列表；
- 在本地验证公开节点连通性与匿名度，组织多跳链路用于学习与测试；
- 通过回环网关与本地入口做协议适配、链状态查询与自动化实验。

## 2. 明确禁止

本项目**不提供、也不得被用于**：

- 网络攻击、未授权扫描、入侵、拒绝服务或凭据窃取；
- 绕过付费墙、身份验证、访问控制或区域授权机制；
- 抓取私有 / 需授权的列表，或规避目标站的访问限制；
- 欺诈、冒充机构、伪造文件或传播虚假信息；
- 侵犯他人隐私、跟踪或骚扰；
- 任何违反适用法律的用途。

代码与文档中的合规边界是设计的一部分，不得以「测试」「学术研究」「假设场景」为由绕过。

## 3. 采集行为的约束

| 约束 | 实现 |
| --- | --- |
| 只采公开免费列表 | `config/sources.yaml` 仅登记公开 Raw 列表与公开 API；自定义源由用户自行负责其合规性 |
| 遵守 robots.txt | `crawler.respect_robots = true`（默认），被拒绝的结果标记 `BLOCKED` 而非反复重试 |
| 遵守服务条款 | 默认关闭超大列表源；启用前需用户自行确认目标站条款 |
| 限速 | 全局令牌桶 `crawler.rate_limit_per_second`（默认 8/s）、隐匿等级并发上限、指数退避 |
| 不自动启用新源 | 仓库检索发现只产出候选，需人工确认后才可启用 |
| 不做身份规避 | 隐匿等级只降低采集端自动化特征，不绕过任何认证或访问控制 |

若某源返回 429 / 403 或 robots 禁止，应降低速率或停用该源，而不是提高重试次数、更换 UA 反复试探。

## 4. 免费公共代理的风险警示

- 节点运营者**可能记录、篡改或注入**流量；明文 HTTP 流量尤其危险。
- 节点可能随时下线、被劫持、被他人控制，或本身就是蜜罐 / 研究观测点。
- 多跳链不会让不可信节点变可信：每一跳都看到元数据，出口节点看到目标地址。
- **绝不要**通过免费公共代理传输真实账号口令、令牌、机密文件、敏感个人信息或未加密的业务数据。
- 不要把本项目当作访问他人系统、绕过限制或隐藏违法行为的工具。

## 5. 高匿不等于绝对匿名

即使使用多跳链与隐匿采集，仍可能无法防御：

- 时序 / 流量模式关联，以及入口与出口的被动观察者；
- DNS 泄漏、WebRTC / 浏览器指纹、应用层账号关联；
- 恶意或被控制的节点运营者、出口节点的内容可见性；
- 本机被入侵、内存取证、键盘记录、屏幕录制；
- ISP、源站或网络级观察者的元数据关联。

需要强隐私或强机密性时，应使用可信的、端到端加密的通道，而不是依赖免费公共代理与本项目。项目文档、CLI 的合规提示（`8 -> 5`）与 `COMPLIANCE` 常量均明确写入该声明。

## 6. 本地数据处理与责任划分

- 节点端点、统计与来源属公开数据；凭证与订阅原文由 Vault 加密保存，Vault 未解锁时不写明文。
- 用户自担自定义源、外部核心二进制（sing-box / xray）、主口令保管与备份安全的责任。
- 导出核心配置（主菜单 `4 -> 9`）与 REST 响应可能含敏感上下文，请勿外传；`to_dict()` 默认已脱敏，但用户显式导出的内容不在保护范围内。
- 日志默认脱敏，但用户自行调高日志级别或关闭 `logging.redact` 会扩大暴露面，需自行评估。

## 7. 维护者承诺

- 不在代码或文档中提供攻击、绕过认证或凭证窃取的指引。
- 不夸大能力：不宣称绝对匿名、不宣称覆盖全网、不把「跳过本地探测」写成「已验证可用」。
- 新增源 / 协议 / 隐匿能力时，同步评估合规影响并更新本文档。
- 发现某源要求授权或禁止自动化采集时，应将其默认禁用或移除。
